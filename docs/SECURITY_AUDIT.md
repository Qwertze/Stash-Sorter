# Security audit

## Scope and trust boundaries

The reviewed code is the Stash Sorter plugin. A Minecraft session, incoming game events, a local command source, the optional remote manager and each build artifact cross different trust boundaries. Assets include stash positions, inventory and delivery records, private chat, the API key and the account owner's console authority. Local directories are assumed to belong to the operator. The server-side manager, upstream proxy implementation, live account and production filesystem were outside the source review.

## Transport, authorization and storage

Manager traffic uses request and response HMACs with nonce, status, timestamp and body verification. Remote manager URLs require HTTPS. HTTP remains available for exact configured loopback hosts. The transport disables redirects, limits response/expanded-body size and sets deadlines. Local tests included an independent request/response MAC implementation, signed gzip, unsigned responses, a redirect, a timeout and connection cleanup. Signature time validation handles pre-epoch values explicitly.

Remote console jobs remain disabled. The restricted settings path still invokes allowlisted setting commands for their local side effects. Proxy-owner authority is not granted to the dashboard source. Existing tests exercise whisper suppression and URL policy. Source review found no incoming web routes or file uploads in the plugin. Web authentication, CSRF, dashboard UI rendering and server-side nonce storage belong to the separate manager.

Stash records, index files, older copies and the manager config are plaintext. Private creation does not retroactively change existing files. Windows ACL inheritance, backup encryption and OS-level compromise require host-side controls. API keys belong in the operator's config. Source distribution checks covered tracked configs and common private-key/token formats. The local API JAR and generated data were excluded from the deliverables.

## Dependency and CI review

The external API fixture had SHA-256 `483dac4972c54aba085a303f39235c88e58000e56ccfb46e3b11358472fc93b5`. This identifies the fixture used here. It does not establish release provenance. The build accepts a separately reviewed tag and SHA-256 for CI. The fixture exposes some embedded version markers, but no Maven `pom.properties` inventories. A complete software bill of materials cannot be inferred from this fat JAR. Obtain the upstream dependency inventory or scan the exact deployed distribution.

The build keeps JUnit test-scoped and moves its BOM to the maintained 5.14 line. JaCoCo 0.8.14 supports the JDK 25 test process. OWASP Dependency-Check 13.0.0 is a build-time scanner. CI uses commit-pinned actions, a read-only token, disabled persisted checkout credentials and no deployment job. The local Gradle bootstrap failed before dependency resolution, so the full direct/transitive scan and hosted CI verification remain outstanding.
